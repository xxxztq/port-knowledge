# 内容维护与校审

## 每个知识节点

说明对象是什么、为什么需要、谁负责、如何交接；提供明确校验项、常见误区、相关节点、来源与适用范围。不要把一家码头的条件写成全国规则。

## 场景结构

每一步使用 actor / action / input / check / output / exception。场景应同时追踪实物、单证、监管、商业授权与实绩。集装箱货物与箱体是两条相关但不等同的生命周期。

## 关键边界

- 出口接收不能统一强制先有海关放行；进口交付另按适用条件判断。
- 海关监管、承运人放货、结算、作业完成、道闸控制与实际通行不互相替代。
- 空箱不是免授权，也不保证无残留；提空入场与最终具体箱号交付的校验时点不同。
- 一车多任务逐项核对；水水中转不强制套入公路闸口。
- 电子口岸、单一窗口、海关与码头系统的拓扑随地方和业务变化。
- 港口集团、码头、船公司及代理的收入归属不同。测算中的数字只能标为假设。

## 建议后续审阅

请熟悉具体港口业务的人员审阅本地规则、异常处理与责任边界。补充资料时记录机构、标题、链接、适用地区、版本时间与核对方式；无法在线读取应如实标注。

本版已有 24 域概览、主要场景和互动入门。重大件、管道、保税转关及更细监管场景等仍可继续深化。不要把覆盖数量当作专业完整性证明。

## 货类与风险如何相互连接

木材、卷钢用独立扩展数据模块维护，统一由 cargo-business.js 导出，避免为每个货种复制页面。每个节点保留 actor / action / system / records / checks / output / exception。风叶进一步包括资料版本、工装占用与回流、项目费用实绩。

风险文件使用 where / signals / prevention / response / owner / partners / records / recovery，并提供相关货类或系统链接与逐项 source 引用。风险总览不计算实际风险等级，不给出统一风速、堆高、堆载或吊重阈值；教学判断不生成操作、监管或恢复指令。

维护时注意：

- 原木、锯材货物与木质包装分别理解；包装标记不替代该票货适用的货物检疫要求。
- 根、片、捆、材积、堆积体积和重量分别保留口径；申报、理货、合同计费的值不能相互覆盖。
- 卷号与炉批关系按厂家资料核对；总重量相同不代表具体货物和货况相同。
- 可见水迹、锈迹及货损记录是事实证据，不是直接确定事故原因或索赔责任。
- 设备修复、生产恢复、系统恢复、数据核对是不同交接，明确决定人、记录及适用范围。
- 法律、国际指导、海外规范、企业产品或项目案例的依据分开记录，不把来源中的示例扩展成全国统一标准。

风险内容、货类关联和学习情景通过 `npm run check:risks` 校验；所有生成页面再检查内部链接、资源及锚点。


## 船型与矿产专题的维护边界

船型数据由 `vessel-types.js` 维护，14 个档案分别说明身份、典型货物、船岸接口、岗位协作、系统记录、费用和风险；`vessel-learning.js` 提供搜索与判断练习。分类用于入门，不把“按货种”“按装卸方式”“按结构”当作互斥分类，也不根据外形替代真实适装审核。辅助船艇单列，避免把拖轮、引航艇、驳船或疏浚船都归为远洋货运船。

矿石和其他干散货分别放在 `cargo-ore-profiles.js`、`cargo-drybulk-profiles.js`，统一导出到货类模板。新增 7 类货物共 52 个业务节点；`mineral-learning.js` 负责原料用途和四种疏港方式。

- 分清矿产品属性与散货、袋装、集装箱等运输形态，不能套用单一作业链。
- 铁矿石、矿粉、球团、铝土矿与细粉、精矿等依据具体货物资料及适用货物条目判断，避免只凭贸易名称判危险性。
- 含水、液化和动态分离采用来源支持的概念说明，不给出自行判断适装的阈值或试验操作。
- 区分 IMSBC 07-23 已生效版本与 08-25 自愿适用期／生效日期；引用新版磷矿粉条目时说明版本，不能泛化为所有磷矿石。
- 煤炭的自热、气体、粉尘等风险分开解释；环保设施、联锁和监测按实际工程设计与专业评估，不给统一喷淋方案。
- 湿吨、干吨、品位、金属量、原始计量、合同认可数量分别记录；原料货款不等于港口服务收入。
- 公路闸口、铁路交接、皮带输送和水水中转使用各自的实物与记录凭据，不能把抬杆作为所有疏港方式的共同节点。
- 来源区分国际规则、政府资料、矿产用途说明、企业船队或项目案例；历史统计不得作为实时进口量、排名或价格。

`npm run check:vessels` 检查船型、矿产学习数据、来源引用、风险关联、搜索及线稿；自动检查与独立内容复核各有范围，不代表全部外链全文或地方业务细则已审定。全文搜索文字在构建时生成，维护新条目时保留正文、别名和来源版本词的检索能力。
